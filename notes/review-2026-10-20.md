## 严重（静默画错，不报错）

### R1. 扇区与 `order` 一起用 → 弧重叠、整圈溢出

`sectors = ` 声明后，`order` 若把同一扇区的节点打散（`order = "hclust"` 最常见，
显式向量也会），布局仍按 `S-1` 个扇区切换预留缝，但实际切换是 `switches` 次：

```r
nodes <- data.frame(id = c(paste0("g",1:4), paste0("h",1:4)),
                    genome = rep(c("A","B"), each = 4))
lk <- ...; circos_layout(lk, nodes = nodes, sectors = "genome", order = "hclust")
# sectors: B,A,A,B,A,B,A,B   切换 6 次，预算只留 1 次
# 4w + 3g + 3sg = 6.849 > 2π = 6.283   → 弧重叠 0.57 弧度
```

实测：`sum(width) + (n-1)g + switches*sg = 7.79`（等于 2π + 1.51）。
图上表现为局部弧形叠加变粗、`geom_sector_label()` 的标签落在别的扇区节点上
（见 `notes/figures/review-sector-overflow.png`）。`sectors=` + `order="hclust"` 是文档里
（README tracks 图、`vignette("tracks")`）都会用到的组合。

根因：§4.3-4 的预算公式 `2π - n·g - (S-1)·sg` 隐含"每个扇区是连续段"，
但没有任何一步强制这一点；`order` 是纯自由排列。

修法（择一，建议 A）：
- **A. 让扇区连续**：`order` 只在扇区内部生效——按扇区首次出现顺序分组，
  组内按用户/`hclust` 给的顺序。静默、不报错、所有组合都合法。
- B. 显式拒绝：`order` 把某扇区打散就 `ggcircos_error_layout`
  （"order must keep each sector's nodes together"）。更保守，但
  `order="hclust"` + `sectors=` 这种自然组合会直接不可用。
- C. 按实际切换次数算预算（`span = 2π - n·g - switches·sg`）。数学上自洽，
  但扇区标签仍然只能是"一个连续段"，语义没救。

### R2. `screen_angle()` 在 `clockwise = TRUE`（默认）下是镜像的

spec §5.4 要求屏幕角与 `transform()` 的切向一致（"唯一来源、禁止 atan2 反推"）。
实测（CW 默认）：

```
theta(deg)      0     90    180   270
clock pos       0     90    180   270
screen_angle    0     90    180   270      ← 返回的是"钟面角"
真实切向(ggplot) 180    90     0     90      ← 差 |180-2θ|
```

四个正交点恰好一致，所以只在斜角处暴露：θ=17° 时错 34°，θ=45° 时错 90°（文字**径向**而立）。

视觉判据（`notes/figures/review-rotate-cw.png` vs `review-rotate-ccw.png`）：把文字与它所在节点的弧叠在一起，
CW 下文字**斜穿弧线**，CCW 下贴着弧走。CCW 分支实测逐点吻合（差 0.000°）。

受影响的默认路径：`geom_node_text(rotate = TRUE)`、`geom_sector_label(angle = "radial")`、
`geom_track_axis()` 的切向标签。轴之所以看着没事，是因为轴立在第一个节点起点
（θ≈0，误差≈0）——巧合掩盖了 bug。

根因：`screen_angle()` 返回的是"钟面角"（`arc` 参数的角度），而 grid 的文字 `rot`
是"从 +x 逆时针"。两者差 90° 且 CW 分支符号相反。正确关系（由 transform 反推的
几何，非 atan2 数值反推）：
`α = 180° - rad_deg`（`reverse = "none"`）/ `α = rad_deg - 90°`（`reverse = "theta"`）。

现有测试只断言 `rotate=TRUE/FALSE` 的 `rot` 不全为 0 / 全为 0（B13 的回归），
没有任何测试断言"角度与切线一致"——spec §5.4-5 要求的那个测试从来没写过。

### R3. `scales = "free"` 实际是**全局**归一化，不是按节点

spec §6.4 的公式给了 `max_i`（下标 i = 节点），即每个节点各自归一化；
实现是 `rescale_from(v, base, max(v), r0, r1)`，`max(v)` 是整列：

```r
# 两个节点 v = 1 和 100
# 实际 x: 1.212 / 1.260   ← 全局 max
# spec:   两个都到 r1     ← 每节点自己的 max
```

后果：`scales="free"` 与 `"fixed"` 的区别退化成"范围从数据来 / 从 limits 来"，
`"free"` 这个名字没有兑现。circlize 的 `circos.track` 与 ggtreeExtra 的 `geom_fruit`
都是按 cell（即节点）归一化的，用户迁移过来会按那个预期读图。

这是**设计题**不是纯 bug：全局归一化对"跨节点比较 GC%"其实更合理。
两条路：(a) 按 spec 实现 per-node；(b) 改 spec + 改名/文档，明确 `"free"` =
"范围由数据决定"，per-node 留给 v0.2。**需要拍板**。

## 中等

### R4. `stack = TRUE` 遇负值：不报错，且画错

spec §6.4 明写要有 `ggcircos_error_data`（"stacking needs non-negative values"）。
守卫确实写在 `track_map_values()` 里（直接调用会报错），但走真实管线时
`data$x` 到达 position 时不是原始值，守卫从不触发：

```r
d <- data.frame(id = c("a","a","b","b"), v = c(-1, 1, 2, 3))
# 实际: a 的第二条从 1.06 起、b 的第一条从 a 的顶端(1.115)续上
#       负值直接被吞掉，堆叠跨节点串联
# spec: 报 ggcircos_error_data
```

`track_stack()` 里 `tot <= 0` 的分支把 `lo = hi = r0` 静默降级，也是同一处的隐患。

### R5. `sector_span()` 平局处理错：单扇区（或各缝等宽）时整段旋转一格

`sector_span()` 用 `which.max(ahead)` 找"扇区不连续处的缝"。当所有缝一样宽
（一个扇区、或 `start` 使首尾缝相等）时 `which.max` 取到**中间**的普通节点缝，
把连续段旋转一格：

```r
circos_layout(data.frame(from="a1", to="a2"),
              nodes = data.frame(id=c("a1","a2")), start = 5.8)
# nodes: a1 5.800→2.596, a2 2.658→5.737
# sectors: theta0 2.658(=a2 起点) theta1 2.596(=a1 终点) theta 2.690
# 正确:   theta0 5.800            theta1 5.737            theta ≈ 2.626
```

`sectors$theta` 落在扇区之外，标签位置就错。修法：最大缝与次大缝之差在容差内
（无真实扇区缝）时取 `k = n`（不旋转），即"整段从第一个节点起算"。

现有测试 `"sector spans follow the ring, not min/max (B1)"` 用的是 A,A,A,B,B,B
的连续布局 + 明确的两条缝，绕开了这个分支。

### R6. 左半圈判据用 `cos(screen)`，与真实左右不一致

spec §5.4-3 定义"屏幕角余弦 < 0 → 左半圈 → `hjust = 1`"。但屏幕角是**切向**，
不是指向外的径向：切向余弦 < 0 对应的是**下半圈**（钟面 90°–270°），不是左半圈
（钟面 180°–360°）。两者在 (90°,180°) 与 (270°,360°) 上相反：

```r
# 实测：am 在 276°（左，x=0.102）判成"右"→ hjust=0，文字向右压进环内
#       wt 在 178°（右，x=0.513）判成"左"→ hjust=1
```

修法：判据改用 `sin(screen) < 0`（等价于 `cos(β) < 0`，β 为径向角），
与 R2 的修正配套。spec §5.4-3 的措辞要一起改。

### R7. 不变量自检形同虚设

spec §4.3-9 要求：失败报 `ggcircos_error_internal`，且要真校验
`sum(节点弧) + gaps == 2π`。实现是：

```r
stopifnot(..., abs(nrow(nd) * (w + g) + (S - 1) * sg - 2 * pi) < 1e-9)
```

- 这是**恒等式**：`span` 就是按这个式子反解出来的，永远成立；它校验的不是
  实际用掉的缝（`offset` 里的 `switch_sector`），所以 R1 那种溢出完全逃过自检。
- 用的是裸 `stopifnot`（报 `simpleError`），不是分类错误。

修法：改成 `sum(nd$width) + sum(实际缝) ` 才算，并用 `ggcircos_abort("internal", ...)`。
这条修好，R1 在构造阶段就会炸，而不是画出一张错图。

## 验过、没问题的部分

- **§4.3 构造算法**：gap 自适应（`min(gap, 0.2/N)`）、`start` 任意实数取模、
  单节点退化、0 链接合法、未知节点/NA/负 gap/`slot_fill` 越界的分类错误。
- **§4.6 槽位几何**：按侧独立分配（3 出 1 入的节点两侧各自铺满，实测
  `theta1-theta0 == p·node_w/d_side`，容差 1e-9），ribbon 脚严格等于槽位。
- **§6.1 chord**：第二层只能取子集（越界报 `ggcircos_error_data`）、
  `curvature` 数值、`arrow`、`alpha` 默认（ribbon 0.5 / line 0.9）、
  连续 fill 分桶（B11，55 边 → 18 grob）。
- **§6.2 节点层**：`fill` 默认常量 `grey30`（不被扇区抢占）、`linewidth` 生效（B6）、
  `rotate` 传输路径（B13）。
- **§7 头函数**：`ggcircos()` 单独合法、y scale 固定、layout 挂 data 属性、
  `.rds` 往返、`+ coord_circos(clockwise = FALSE)` 可覆盖。
- **§8 只读契约**：四个 `ggplot_add` 不碰 `plot$data/mapping/scales`；
  访问器返回副本；position 只持向量（§8.2）。
- **§9.1 甲方案 facet**：弦按 panel 切、节点环与轨道每 panel 复制一份，实测行数吻合。
- **§10 主题**：`bgcolor` 同时设 plot/panel 背景（B9）、`grid=TRUE` 不产生
  "theme element not defined" 警告。
